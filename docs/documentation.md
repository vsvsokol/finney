## 1. Назначение и состав репозитория (п. 5.1)

«Питомец Финни» — офлайн-игра для Android, в которой дети 7–11 лет учатся обращаться с
деньгами: планировать бюджет, отличать нужное от желаемого и копить на цель. Ребёнок получает
игровой доход, делит его между обязательными тратами, желаниями и копилкой — и сразу видит
последствия на питомце. Ошибка ничего не обнуляет: она объясняется и остаётся уроком.

Вся валюта условная. Реальных денег, платежей, рекламы, аккаунтов и сбора персональных данных
нет (ТЗ п. 2.7, 3.5).

| Путь | Что там |
|---|---|
| `app/` | модуль приложения: Kotlin, Jetpack Compose |
| `app/src/main/assets/content/` | учебный контент и баланс в JSON |
| `app/src/test/` | 222 unit-теста экономики, мини-игр, контента и экранов |
| `app/src/androidTest/` | инструментальные тесты базы и миграций |
| `app/schemas/` | схема базы Room каждой версии |
| `docs/` | документация (этот файл и подробные разделы) |
| `design/exports/` | готовая графика от дизайнеров |
| `tools/` | скрипты подготовки графики (Python) |
| `.github/` | CI и правила ревью |

Быстрый старт — раздел 2. Статус требований — раздел 5.

## 2. Окружение и сборка APK (п. 5.2)

| Инструмент | Версия |
|---|---|
| Android Studio | Quail 4 (2026.1.4) или новее |
| JDK | 25 — JetBrains Runtime внутри Android Studio |
| Android SDK | Platform 37 (compileSdk / targetSdk), Platform-Tools |
| Kotlin / Gradle / AGP | 2.4.20 / 9.6 / 9.4 — приходят с проектом |
| Минимальная версия Android | 8.0 (minSdk 26) |

**Запуск из Android Studio.** `git clone https://github.com/vsvsokol/finny.git`, открыть папку,
дождаться синхронизации Gradle, запустить конфигурацию `app`.

**Отладочная сборка из терминала:** `./gradlew assembleDebug` (Windows — `gradlew.bat`).
Результат — `app/build/outputs/apk/debug/`. Готовая отладочная сборка каждого PR лежит в
артефакте `finney-debug-apk` на вкладке Actions репозитория.

**Релизная сборка.** Ключ подписи в репозиторий не попадает (ТЗ п. 3.4).

1. Создать ключ рядом с папкой репозитория:
   `keytool -genkeypair -v -keystore ../finney-release.jks -storetype PKCS12 -keyalg RSA -keysize 2048 -validity 10000 -alias finney`.
2. Скопировать `keystore.properties.example` в `keystore.properties` и заполнить пароли
   (файл в `.gitignore`).
3. `./gradlew assembleRelease` → `app/build/outputs/apk/release/app-release.apk`.
   Без `keystore.properties` сборка не падает, а выдаёт неподписанный APK.

Версия — `version.properties` (`major.minor.patch`), `versionCode` считается из неё сам.
**Сборка для сдачи 29.09 — 0.10.0 (versionCode 1000)**, подписанный APK и тег `v0.10.0` —
<https://github.com/vsvsokol/finny/releases>. Пакет — `ru.finney.pet`.
Переменные окружения для терминала (`JAVA_HOME`, `ANDROID_HOME`) — README, «Переменные окружения».

**Демо-режим.** На первом запуске — «Режим проверки (демо)», или переключатель «Демо» в
«Настройках». Все мини-игры открыты, для уровня хватает 1 условия из 3, игра уровня — по
желанию, сон и напоминания короткие: пять периодов проходятся за несколько минут, и за них
питомец показывает все три облика роста.

**Сброс.** Меню главного → «Настройки» → раздел взрослого (барьер — пример на умножение) →
«Начать игру заново» (питомец остаётся, прогресс с первого уровня) или «Удалить профиль»
(возврат к первому запуску).

## 3. Архитектура (п. 5.3)

Серверной части нет: весь игровой цикл работает на устройстве, офлайн (ТЗ п. 3.1).

| Слой | Технология |
|---|---|
| Интерфейс | Jetpack Compose + Material 3, ViewModel + Flow |
| Навигация | Navigation Compose, маршруты — `@Serializable`-объекты |
| Ядро игры | чистый Kotlin без Android: `domain/` |
| Хранение | Room (SQLite) — профиль и история; DataStore — настройки |
| Учебный контент | JSON в `assets/content/`, kotlinx.serialization |
| Уведомления | WorkManager, только локальные |
| Зависимости | ручной контейнер `AppContainer` |

```
ru.finney.pet
├── ui/             экраны, мини-игры, анимация питомца, звук    — зависит только от domain
├── navigation/     граф экранов
├── domain/         экономика: план, покупки, копилка, уровни, движки заданий
├── data/           Room и DataStore — реализация интерфейсов domain
├── content/        загрузка и проверка JSON (ContentValidator)
└── notifications/  локальные напоминания
```

Главные правила:

- **Экраны знают только ядро.** `ui` не обращается к `data`; зависимости приходят из
  `AppContainer` через фабрики ViewModel.
- **Ядро — чистые функции.** `Game` получает состояние и команду и возвращает новое состояние
  или отказ с причиной (`Rejection`). Ядро не знает про Android, поэтому покрыто обычными
  unit-тестами без устройства.
- **Команды идут по очереди** через `GameStore` / `Session`: двойное нажатие не спишет
  деньги дважды.
- **Контент отделён от кода.** Новое задание — запись в `tasks.json`; `ContentValidator`
  при загрузке и в тестах проверяет, что игру можно и выиграть, и проиграть (ТЗ п. 2.5.14).

Подробно — `docs/architecture.md`.

## 4. Структура данных (п. 5.4)

В базе хранятся **факты** — что произошло. Всё, что из них считается (баланс, накопления,
уровень, эмоция), не хранится, поэтому число на экране не может разойтись с историей.

| Таблица | Что хранит |
|---|---|
| `profiles` | имя питомца, персонаж, цвет тела, вариант глаз, активная цель, признак демо, дата создания |
| `pet_state` | сытость, чистота, настроение, энергия |
| `periods` | номер уровня, фаза; план (бюджет и три направления) и итоги уровня |
| `ledger` | операции: тип, изменение баланса и копилки, категория, товар, цель, задание, время |
| `task_attempts` | попытки заданий: исход, награда, время, зерно случайных чисел |

Все таблицы ссылаются на профиль с `ON DELETE CASCADE`. Операции и попытки только дописываются.
Схема — версия 10, каждая версия экспортирована в `app/schemas/`; с версии 3 изменения
переносятся миграциями, и прогресс сохраняется при обновлении (инструментальный `MigrationTest`).

| Величина | Как считается |
|---|---|
| Баланс | сумма изменений баланса по `ledger` |
| Копилка цели | сумма изменений копилки по цели |
| Факт уровня | сумма операций уровня по категориям |
| Уровень | число пройденных уровней |
| Стадия роста | по уровню и порогам `stageStartLevels` |
| Пройденные задания | попытки с исходом «успех» |

Контент — шесть файлов JSON: `tasks.json` (мини-игры), `shop.json` (товары), `goals.json`
(цели), `economy.json` (все числа баланса), `feedback.json` (тексты эмоций, итогов, отказов),
`glossary.json` (справочник). Схемы полей — `docs/minigames.md`, `docs/economy.md`.

## 6. Правила экономики (п. 5.6)

Игра идёт **уровнями** — это игровой период ТЗ, не привязанный к календарю.

```
начало уровня → доход, шкалы питомца снизились
   → план: доход на нужное, желаемое и копилку (все три > 0, без перерасхода)
   → решения: покупки, мини-игры, взносы в копилку
   → итоги: план против факта, условия уровня → следующий уровень
```

| Правило | Значение (`economy.json`) |
|---|---|
| Доход уровня | 50 / 55 / 60 / 65 / 70 / 70 — растёт со стадией |
| Мини-игра | +15 за успех, +5 за первую неудачную попытку, +5 бонус в «Дождливом дне» |
| Бонус взрослого | 5–20 монет за уровень, шаг 5 |
| План выполнен | перерасход не больше незапланированного дохода + 5 |
| Уровень пройден | игра уровня пройдена и выполнено 2 из 3 условий: нужное обеспечено, план выполнен, копилка пополнена |
| Уровни и стадии | 30 уровней, шесть стадий — с уровней 1, 2, 4, 6, 12, 20; уровень никогда не уменьшается |
| Цели | шесть, 90–170 монет в копилке; достигнутая цель отдаёт питомцу шляпу или очки |
| Сон | энергия падает за уровень; сон 4–30 минут по стадии, первые два уровня без сна; во сне облачко загадывает слово из справочника — верный ответ радует питомца, но сон не ускоряет |
| Игры уровня | на уровне три игры: обязательная и две по желанию из других серий, за каждую награда |
| Баланс | сумма операций; операция, которая увела бы в минус, не записывается, а отказ объясняет нехватку |

**Состояние питомца** — шкалы 0–100: сытость, чистота, настроение, энергия. В начале уровня
они снижаются (больше на старших стадиях), покупки и уход их восстанавливают. Ниже 50 —
питомцу «нужно»; эмоция считается по шкалам и объясняется ребёнку одной строкой
(«голоден — покорми на кухне»).

Два инварианта проверяются тестом на каждой стадии: **нет тупика** (доход покрывает нужное
даже из нулевых шкал) и **есть выбор** (после нужного при обычной игре остаётся не меньше
20 монет). Полные формулы, симуляция баланса и список инвариантов — `docs/economy.md`.

## 7. Карта образовательного контента (п. 5.7)

Темы — три темы ТЗ п. 2.5.8. Каждое задание — мини-игра с действием, а не выбор ответа.
У каждой игры три варианта сложности, они открываются с уровнем питомца.

| Игра | Тема | Навык | Сценарий | Правильная логика | Объяснение ребёнку (успех) |
|---|---|---|---|---|---|
| Конвейер | планирование | отличать нужное от желаемого | вещи едут по ленте, их разносят в две корзины | нужное — то, без чего питомцу станет плохо | «Сначала покупают нужное, а желаемое — если остались монеты» |
| Дождливый день | планирование | оставлять запас | неделя на 60 монет, случаются сюрпризы | нужное не перенесено; бонус — если сохранено и желаемое | «Запас — это деньги на всякий случай» |
| Лимонадная лавка | планирование | получил − потратил = осталось | купить лимоны под число гостей | сырья ровно на всех гостей | «Считать заранее — выгодно» |
| Подработка | планирование | деньги за работу, время — ресурс | неделя дел ради цели | заработать на цель и оставить день отдыха | «Менять дела и отдыхать выгоднее» |
| Дорога к цели | сбережения | копить понемногу, но регулярно | доход каждый день, соблазны по пути | накопить на цель и не оставить питомца без радости | «Откладывать понемногу, но каждый день — так и копят» |
| Список покупок | платежи и покупки | покупать по списку в пределах денег | собрать корзину, сравнить упаковки | всё по списку и не выйти за лимит | «5 яблок за 20 выгоднее, чем 2 за 10» |
| Касса Финни | платежи и покупки | сдача и оплата без сдачи | отсчитать сдачу, заплатить ровно | сдача = дали − стоит | «Всегда проверяй сдачу» |
| Проверь чек | платежи и покупки | сверять чек с покупками | найти ошибку кассира | отмечены все ошибки и ничего лишнего | «Проверять чек — это нормально» |

Объяснение показывается при любом исходе; при неудаче — с подсказкой, что сделать иначе.
Правила текстов: короткие фразы, счёт в пределах круглых чисел, без стыда и страха, без
банковских продуктов и реальных брендов. Условия успеха и схемы полей — `docs/minigames.md`,
правила текстов — `docs/content-tasks.md`, термины — `glossary.json` (раздел «Справочник»).

## 8. UX/UI и доступность (п. 5.8)

**Почему интерфейс такой.**

- **Комната вместо меню.** Главный экран — комната питомца: деньги ведут в магазин, кольца на
  кнопках кухни и ванной показывают сытость и чистоту. Всё нужное — на одном экране (ТЗ 2.5.3).
- **Покупка — действие.** Еду бросают в рот, мыло трут; монеты списываются, когда действие
  случилось. До покупки видны цена, категория и влияние на шкалы, после — «было → стало».
- **Сначала план, потом траты.** Покупки и копилка открываются только после плана — так
  механика сама учит порядку «спланировал → потратил».
- **Без стыда и страха.** Отказ объясняет, чего не хватает и что сделать; уровень никогда не
  уменьшается, питомец грустит, но не болеет и не умирает (ТЗ 2.2, 8.1).
- **Меньше текста — больше показа.** По итогам плейтеста: подсказки пульсом на первом ходе,
  полоски, кольца и банки плана у чисел «сколько из скольки», итоги игр блоками, «−/+» можно
  держать. Справочник — в меню главного, его слова загадывает облачко над спящим питомцем.

**Доступность (ТЗ п. 3.6).**

| Требование | Как сделано |
|---|---|
| Элементы от 48×48 dp | кнопки от 64 dp, круглые от 56 dp, чекбоксы и шаги от 48 dp |
| Текст от 16 sp | основной текст 20 sp, подписи 17 sp, заголовки — шрифт Glina Script |
| Не только цветом | низкие шкалы — значок и «!», выражение лица питомца, полное — «✓», перебор — «!», штриховка превью копилки |
| Единая кнопка возврата | круглый «✕» 48 dp в правом верхнем углу на всех экранах, описание «Назад» |
| Экранный диктор | у кнопок-значков описания для TalkBack, «−/+» нажимаются действием |
| Звук и анимации | звук, музыка, анимации и вибрация выключаются по отдельности в «Настройках» |
| Экран | портретная ориентация, ширина от 360 dp |

## 9. Разрешения, данные и удаление (п. 5.9)

| | |
|---|---|
| Разрешения | одно — `POST_NOTIFICATIONS` (Android 13+) для локальных напоминаний; спрашивается один раз, отказ игру не ломает. Интернета, геолокации, камеры, контактов нет |
| Какие данные | игровое имя питомца, его внешность, игровая история (операции, попытки, итоги уровней), настройки звука и анимаций. Реального имени, телефона, e-mail, аккаунта нет |
| Где хранятся | только на устройстве, в базе приложения; на сервер ничего не передаётся |
| Резервная копия | выключена (`allowBackup=false`), чтобы удалённый профиль не восстановился |
| Удаление | раздел взрослого → «Удалить профиль»: все данные профиля удаляются каскадно одним запросом; «Начать игру заново» сбрасывает прогресс. Удаление приложения стирает всё |

## 11. Ограничения прототипа и план развития (п. 5.11)

**Известные ограничения.**

- Стадий роста шесть, а обликов на рисунке три: стадия 1, стадии 2–3 и 4–6 (уровни 1, 2–5 и
  с 6-го). Облики получены увеличением туловища, рук и ног, а не отдельной графикой.
- Цвет тела получается сдвигом оттенка слоёв; готовые расцветки художника — в плане.
- Часть звуков — синтетические заглушки (`design/exports/sounds/README.md`), настоящие кладутся
  поверх с тем же именем без правки кода.
- Плейтесты проводила команда; с детьми игру ещё не проверяли (раздел 10).
- На планшетах с Android 16+ система не даёт закрепить портрет; альбомная раскладка по ТЗ не
  обязательна и не делалась.
- Черновик карточки RuStore готов (`docs/rustore/`), публикации нет — ТЗ её не требует (п. 2.7).

**План до финала** (ответственные — в `docs/requirements-matrix.md`):

1. Проверка с детьми (с согласия родителей) — понимают ли разделы без инструкции.
2. Настоящие звуки и расцветки питомца вместо заглушек.
3. «Лимонадная лавка» на несколько дней — логика и тест готовы, нужен экран.
4. Публикация в RuStore по готовому черновику карточки.

**Дальше.** Бонус за радость питомца (настроение влияет на доход), расцветки вместо сдвига
оттенка, случайные события внутри уровня, новые мини-игры и темы Единой рамки финансовой
грамотности — правкой контента, без изменения кода.

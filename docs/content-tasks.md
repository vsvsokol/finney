# Учебный контент: задания

Черновик для [@vsvsokol]. Закрывает ТЗ п. 2.5.8 и минимум п. 2.6 — **6 заданий по 3 темам**.

## Ограничения ТЗ, которые нельзя нарушать

> «Задания представляют собой игровую ситуацию с выбором и последствиями, и **не ограничиваются выбором ответа из предложенных вариантов**» (2.5.8)

Викторина «выбери правильный ответ» требование **не закрывает**. П. 8.1 отдельно оценивает «соответствие механики образовательным результатам, **а не формальное добавление тестов**». Ребёнок должен что-то двигать, распределять или собирать.

Остальное:
- объяснение показывается **после любого исхода**, включая неудачный (2.5.8);
- сложность формулировок и вычислений — возраст 7–11 лет (2.5.8);
- в демо-режиме все задания доступны сразу (2.5.8);
- проверяется прохождение **правильного и ошибочного** варианта (2.6).

Темы заданы ТЗ жёстко, свои придумывать нельзя: **планирование бюджета**, **формирование сбережений**, **платежи и покупки**.

## Три движка вместо шести экранов

П. 2.5.14 требует, чтобы новое задание добавлялось без переработки логики. Поэтому задание — это конфиг поверх одного из трёх механизмов.

| Движок | Что делает ребёнок | Темы |
|---|---|---|
| `distributor` | раскладывает сумму по корзинам ползунками | бюджет, сбережения |
| `basket` | набирает корзину в рамках лимита | покупки |
| `goal_slider` | подбирает размер регулярного взноса под срок | сбережения |

[@lemonke68] делает три движка, [@vsvsokol] насыпает заданий сколько угодно.

**Формальная схема каждого движка, правила успеха и выдача наград — [economy.md, раздел 9](economy.md#9-задания).**
Коротко:

- условия успеха задаются списком `rules`, успех — когда выполнены все правила;
- в `basket` оплата сверх `limit` не исход, а отказ «не хватает N монет» — ребёнок убирает лишнее и пробует снова;
- награда по умолчанию берётся из `economy.json` (15 за успех, 5 за первую неудачу), поле `reward` в задании её переопределяет;
- `unlockPeriod` — с какого периода задание открыто, по умолчанию 1; в демо-режиме игнорируется.

## Шесть заданий

### 1. «Разложи по конвертам» — планирование бюджета

```json
{
  "id": "budget_01",
  "theme": "planning",
  "engine": "distributor",
  "title": "Разложи по конвертам",
  "intro": "Финни получил 60 монет. Помоги распределить их на неделю.",
  "amount": 60,
  "baskets": [
    { "id": "needs",   "label": "Нужное",  "hint": "еда и шампунь" },
    { "id": "wants",   "label": "Хочется", "hint": "игрушки" },
    { "id": "savings", "label": "Копилка", "hint": "на цель" }
  ],
  "rules": [
    { "type": "min", "basket": "needs",   "value": 25 },
    { "type": "min", "basket": "savings", "value": 5 }
  ],
  "explainOk": "Ты закрыл всё нужное и ещё отложил. Финни сыт, а цель стала ближе.",
  "explainFail": "На нужное не хватило. Финни проголодается. В следующий раз сначала закрой обязательное, потом остальное."
}
```

## Вопросы по заданиям — [@vsvsokol]

1. **`budget_02`.** Без правила `excludes robot` набор «робот + яблоко» (ровно 40) проходил бы как успех:
   еда в корзине есть. Правило добавлено — проверь, что задумка именно такая.
2. **`savings_02`.** Игрушка стоит ровно 40, поэтому любое распределение, кроме «всё в копилку»,
   игрушку не покупает — фактически это выбор из двух вариантов, а п. 2.5.8 и 8.1 такое не засчитывают.
   Предложение: игрушка за 25, успех — в копилку не меньше 15. Тогда есть реальное распределение.
3. **`shopping_02`.** Добавлен сценарий «уложился, но убрал еду» — `explainFail` переписан под него.
   Старый текст («денег всё ещё не хватает») теперь показывает сам отказ оплаты, а не исход.

## Правила написания текстов

По ТЗ п. 3.6 и 8.1:

- короткие фразы, простые слова, без финансовых терминов без объяснения;
- арифметика в пределах круглых чисел и таблицы умножения;
- **не стыдить и не пугать**: «Финни расстроился, но всё поправимо», а не «Финни голодает по твоей вине»;
- в объяснении неудачи всегда есть следующий шаг — ТЗ п. 2.5.9;
- термины, которые всё же вводятся, попадают в `glossary.json` (п. 2.5.11).

## Чего в текстах быть не должно

- слов «донат», «платёж», «купить за реальные деньги» — ТЗ п. 2.7.2 и 3.5;
- процентов по вкладам, кредитов, банковских продуктов — п. 2.2 «финансовая нейтральность»;
- названий реальных банков, брендов и магазинов — п. 2.2.

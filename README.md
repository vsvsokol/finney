# Питомец Финни

Мобильное приложение для Android: виртуальный питомец, через которого дети 7–11 лет
осваивают планирование бюджета, приоритезацию трат и накопления.

Хакатон «Лидеры цифровой трансформации» 2026. Техническое задание — [docs/manual.pdf](docs/manual.pdf).

> Игровая валюта условна. Реальные деньги, платежи, реклама и сбор персональных данных
> в приложении не используются (ТЗ п. 2.7, 3.5).

### 20 сентября — пятеро питомцев на выбор · [@zYafALL]

Касается [@vsvsokol]: питомцев на экране создания профиля теперь пять, и трём новым нужны
настоящие имена — стоят заглушки «Звёздочка», «Бантик» и «Лучик». Касается [@mitzzi4] и
[@Lix2w78]: рисунки дошли до игры без правок, перерисовывать ничего не нужно.

- `PetCharacter` пополнен значениями `ZVEZDOCHKA`, `BANTIK`, `LUCHIK`, слои перенесены в
  `drawable-nodpi` через `tools/split_pet_base.py`. APK вырос с 14.3 до 15.1 МБ.
- Точки вращения вычисляются, а не подбираются: плечо — верхний внутренний угол альфы
  слоя руки, бедро — центр верха слоя ноги, опора — низ силуэта. На [@Lix2w78] и [@lemonke68]
  правило сходится с тем, что стояло в коде, с точностью до пары пикселей.
- Экран выбора переведён с `Row` на `LazyRow`. Пять карточек с `weight(1f)` на 360 dp
  ужимались до полусотни точек, а каждая карточка крутит свою анимацию — пять сразу
  вернули бы просадку до 5 fps, которую чинили 18 сентября. В `LazyRow` одновременно
  живут только видимые.
- Миграция Room не понадобилась: `petCharacter` — `TEXT`, новые значения перечисления
  схему не меняют. Старые профили открываются как раньше.

Проверено на Galaxy A25 5G (`SM-A256E`), Android 16, 1080×2340 при density 450 — это
384 dp, шире самого узкого случая по ТЗ п. 3.1. Все пятеро рисуются без шва по контуру.
Вёрстку `LazyRow` на живом экране создания профиля ещё не смотрели: профиль уже создан,
а ломать сохранённый прогресс ради проверки не стали.

### 16 сентября — сохранение прогресса · [@lemonke68]

Касается [@zYafALL]: экраны теперь берут всё из `container.gameStore`.

- **Room**: профили, шкалы питомца, периоды, операции, попытки заданий. Прогресс переживает закрытие
  приложения (ТЗ п. 2.5.13). Удаление профиля убирает все его данные — это сброс тестового профиля.
- **`GameStore`** — через него работают экраны: `createProfile`, `updateProfile` (повторная настройка
  внешности), `execute(profileId) { команда }`, `submitTask`, `observeProfiles`, `observeGame`,
  `deleteProfile`, `deleteAll`. Каждая команда сразу сохраняется, команды идут строго по очереди.
  Примеры — [docs/architecture.md](docs/architecture.md), раздел «Как устроен domain».
- **Внешность питомца**: `BodyColor` (A/B/C) × `EyesVariant` (ROUND/OVAL/SLY) = 9 комбинаций.
  Имя питомца: 1–16 символов, пробелы по краям обрезаются.
- **Глоссарий** [@vsvsokol] (`glossary.json`) загружается вместе с остальным контентом и проверяется.
- Тесты: 41 unit-тест, плюс 4 instrumented-теста на эмуляторе Android 8.0 — сохранение переживает
  переоткрытие базы, сохранённое состояние совпадает с игрой в памяти, удаление профиля чистит все таблицы.
  Instrumented-тесты в CI не запускаются — только локально на эмуляторе или устройстве.
- **Исправление**: в `economy.md` было написано, что `BackupManager.dataChanged()` ускоряет резервную
  копию. Это неверно — на Auto Backup он не влияет. Раздел 10 и вопрос 9 ниже исправлены.

### 16 сентября — спецификация экономики · [@lemonke68]

Касается всех, кто пишет задания, товары, тексты и экраны бюджета.

- **[docs/economy.md](docs/economy.md)** — единые правила игры: фазы периода, план и факт,
  покупки, шкалы питомца, копилка, очки и стадии, схемы заданий. Числа по умолчанию проверены
  симуляцией 5 периодов: тупиков нет, все 3 стадии видны за демо-сценарий.
- **Период в три фазы**: планирование → активная фаза → закрыт. Тратить до подтверждения плана нельзя.
- **Баланс и накопления не хранятся**, а считаются из истории операций — поэтому число
  на экране всегда совпадает с историей.
- **Копилка ведётся по каждой цели отдельно.** При смене цели накопленное не пропадает.
- **Задания**: условия успеха — списком `rules`, награда по умолчанию из `economy.json`.
  Все 6 заданий в [docs/content-tasks.md](docs/content-tasks.md) переведены на новую схему.
- **Очки**: новый уровень каждые 5 очков (было 3), иначе уровень 9 достигался к 3-му периоду.
- **Шкалы питомца**: сытость, чистота, настроение. Усталости нет — она не связана с финансовыми решениями.
- [docs/architecture.md](docs/architecture.md): модель Room переписана под эти правила.

### Переменные окружения

Нужны только для сборки и `adb` из терминала — из Android Studio всё работает и без них.
`JAVA_HOME` указывает на Java, встроенную в Android Studio: если в системе стоит другая
(например, 26), без этой переменной сборка из терминала упадёт.

macOS — в `~/.zshrc`:

```bash
export ANDROID_HOME="$HOME/Library/Android/sdk"
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
export PATH="$PATH:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator"
```

Linux — в `~/.bashrc` или `~/.zshrc` (путь к Studio зависит от способа установки, для snap — `/snap/android-studio/current`):

```bash
export ANDROID_HOME="$HOME/Android/Sdk"
export JAVA_HOME="/opt/android-studio/jbr"
export PATH="$PATH:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator"
```

Windows — `Параметры → Система → О системе → Дополнительные параметры → Переменные среды`:

```
ANDROID_HOME = %LOCALAPPDATA%\Android\Sdk
JAVA_HOME    = C:\Program Files\Android\Android Studio\jbr
Path        += %ANDROID_HOME%\platform-tools
```

## Подпись релиза

Ключ подписи и пароли в репозиторий не попадают (ТЗ п. 3.4). Релиз подписывает [@lemonke68].

1. Ключ создаётся один раз и лежит **рядом с папкой репозитория, а не внутри неё** —
   именно такой путь `../finney-release.jks` прописан в `keystore.properties.example`.
   Из корня репозитория:
   ```bash
   keytool -genkeypair -v -keystore ../finney-release.jks -storetype PKCS12 -keyalg RSA -keysize 2048 -validity 10000 -alias finney
   ```
   В формате PKCS12 пароль ключа совпадает с паролем хранилища: `storePassword` и `keyPassword`
   в `keystore.properties` одинаковые.
2. Скопировать `keystore.properties.example` в `keystore.properties` и заполнить. Файл в `.gitignore`.
3. Резервная копия `.jks` и паролей — ещё у одного человека в команде. Без ключа приложение
   нельзя обновить в RuStore: только публиковать заново под другим именем пакета.

```bash
./gradlew assembleRelease
```

Готовый файл: `app/build/outputs/apk/release/app-release.apk`. Если `keystore.properties` нет,
сборка не падает, а выдаёт `app-release-unsigned.apk` — так CI и остальная команда не зависят от ключа.
Неподписанный APK на устройство не установится.
